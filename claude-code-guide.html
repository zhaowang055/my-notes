Claude Code 完全指南（从入门到进阶）

什么是 Claude Code？

💡 一句话理解：Claude Code 是一个住在你终端（命令行）里的 AI 编程助手。你用自然语言告诉它想做什么，它就能帮你读代码、写代码、运行命令、管理文件——就像一个随时在线的程序员搭档。

它能做什么？

能力 举例
📖 阅读和理解代码 "帮我解释一下这个项目的代码结构"
✏️ 编写和修改代码 "帮我写一个 Python 快速排序函数"
🖥️ 执行终端命令 "帮我运行 npm install"
🐛 调试和修复 Bug "这段代码报错了，帮我找原因并修复"
📁 管理文件 "帮我在 src 目录下创建一个新的组件文件"
🔍 搜索代码库 "帮我找到所有调用 getUserInfo 的地方"

它和 ChatGPT / 网页版 Claude 有什么区别？

对比项 ChatGPT / 网页版 Claude Claude Code
运行环境 浏览器里聊天 你电脑的终端里
能否读你的代码 不能，需要你手动粘贴 能，直接读取你的项目文件
能否修改文件 不能 能，直接帮你创建和编辑文件
能否运行命令 不能 能，帮你在终端执行命令
适用场景 通用问答、写小段代码 真正的项目开发工作

0前置知识：在开始之前你需要了解的概念

📚 如果你从未接触过编程，这一章会帮你理解后面会反复出现的几个基本概念。已经有一定基础的同学可以跳过。

0.1 什么是终端（Terminal）/ 命令行？

你平时怎么操作电脑？ 点击图标、双击文件、右键菜单——这叫"图形界面"。

终端是另一种操作电脑的方式：你输入一行文字命令，电脑执行后把结果显示出来。

举个例子：

- 图形界面操作：打开文件管理器 → 找到文件夹 → 右键 → 删除

- 终端操作：输入 rm -rf 文件夹名 → 回车 → 完成

为什么 Claude Code 要用终端？ 因为终端是最高效的"人机对话"方式。Claude Code 住在终端里，你在终端里和它用文字对话，它就能帮你操作电脑。

怎么打开终端？

系统 打开方式
Windows 按 Win + X，选择"Windows PowerShell"或"终端"；或者在开始菜单搜索"PowerShell"
Mac 按 Command + 空格，输入 Terminal，按回车

打开后你会看到一个黑色（或蓝色）的窗口，里面有一个闪烁的光标，等待你输入命令。这就是终端。

💡 小技巧：建议把终端固定到任务栏/Dock 栏上，后续你会经常用到它。

0.2 终端基础命令速查（5 个就够了）

你不需要成为终端高手，以下 5 个命令覆盖了 90% 的日常操作：

命令 含义 例子
pwd 我在哪？（显示当前路径） pwd → /Users/yourname
ls / dir 这里有什么？（列出文件） ls → 显示当前目录文件列表
cd 文件夹名 去别的地方（进入目录） cd Desktop → 进入桌面
mkdir 文件夹名 创建新文件夹 mkdir my-project → 创建项目目录
clear 清空屏幕 屏幕太乱时用
🎯 练习一下：打开终端，依次执行 pwd → ls → cd Desktop → mkdir ai-tools → cd ai-tools。如果每一步都成功了，终端入门完成！

0.3 什么是目录/文件夹和根目录？

"目录"就是"文件夹"，两个词是同一个东西。程序员习惯叫"目录"。

根目录就是你项目文件夹的最顶层：

my-website/            ← 这就是项目根目录<br>├── src/               ← 源代码目录<br>│   ├── index.js<br>│   └── style.css<br>├── package.json       ← 项目配置文件<br>└── README.md          ← 项目说明文件<br>

为什么 Claude Code 要在根目录启动？ 因为启动后它会自动扫描当前目录的所有文件。在子目录启动就像只翻开书的其中一页，看不到全貌。

0.4 什么是 Node.js？什么是 npm？

Node.js 是一个让 JavaScript 代码能在电脑上运行的环境。Claude Code 是用 JavaScript 写的，所以需要 Node.js 才能运行。

npm 是 Node.js 的"应用商店"，用来安装各种工具。npm install xxx 就像在应用商店点"安装"。

npm 随着 Node.js 一起安装，装了 Node.js 就自动有了 npm。

0.5 什么是项目依赖（Dependencies）？

依赖就是你的项目需要用到的"别人的代码"。 比如你做网站需要用到 React（别人写好的 UI 框架）。

package.json 是项目的"购物清单"，记录了需要哪些依赖。npm install 就是按清单把所有依赖下载下来。

0.6 什么是 .md 文件？

.md 是 Markdown 文件，一种简单的排版语言，用纯文本就能写出带格式的文档。飞书、Notion 底层很多都是 Markdown。后面创建 Skill 和 CLAUDE.md 时都是写 .md 文件。

1环境准备与安装

1.1 安装 Claude Code

Claude Code 提供了原生安装器，不需要安装 Node.js 也能用，一行命令搞定。

Mac 用户：

curl -fsSL https://claude.ai/install.sh | bash<br>
💡 备选方案：如果 Mac 上装了 Homebrew，也可以用 brew install --cask claude-code 安装。

Windows 用户（PowerShell）：

irm https://claude.ai/install.ps1 | iex<br>

Windows 用户（WSL，推荐）：

WSL（Windows Subsystem for Linux）可以让你在 Windows 里运行 Linux 环境，Claude Code 在 Linux 下运行最稳定。

第一步，以管理员身份打开 PowerShell（右键「开始」菜单 → Windows PowerShell（管理员））：

wsl --install<br>

安装完成后电脑会要求重启，重启后自动弹出 Ubuntu 设置窗口，设置用户名和密码（可以设简单一点，但要记住）。

设置完成后，打开「开始」菜单搜索 Ubuntu，在 Ubuntu 终端里：

curl -fsSL https://claude.ai/install.sh | bash<br>
⚠️ Windows 用户注意：后续所有终端命令，WSL 方式请在 Ubuntu 终端执行；PowerShell 方式请在 PowerShell 执行。

验证安装：

claude --version<br>

看到版本号说明安装成功。

💡 不想用命令行安装？ 也可以在 VSCode 扩展商店搜索 "Claude Code" 安装，直接在编辑器里使用。

1.2 认证登录

安装好后需要连接你的账号。推荐两种方式：

方式一：API Key（推荐 ⭐）

API Key 是一串密钥，类似于你的「AI 使用通行证」。按使用量付费，用多少扣多少，灵活且经济。

1. 访问 console.anthropic.com，注册账号

1. 在 API Keys 页面点击 Create Key，给密钥起个名字（如 my-first-key）

1. 页面会显示以 sk-ant- 开头的密钥。立刻复制并保存到安全的地方，因为它只会显示一次！

1. 在 Billing 页面添加付款方式，设置月度上限（如 $20）

1. 在终端设置环境变量：

# Mac/Linux<br>export ANTHROPIC_API_KEY="sk-ant-你的密钥"<br><br># Windows PowerShell<br>$env:ANTHROPIC_API_KEY="sk-ant-你的密钥"<br>
🔐 让 API Key 永久生效（推荐）：上面的命令只在当前终端窗口有效，关掉就失效了。要永久生效：

方式二：Claude Pro/Max 订阅

如果你已经在使用 claude.ai 的付费订阅（Pro 或 Max 计划），可以直接用订阅账号登录。

直接在终端输入 claude，会弹出浏览器让你用 claude.ai 账号登录。

📌 该选哪个？ 如果只用 Claude Code，推荐 API Key（按量付费更灵活）。如果同时还在 claude.ai 网页端使用，选 Pro/Max 更划算。

确认登录成功：

claude doctor<br>

所有项目显示绿色 ✓ 就说明一切正常。

💰 费用参考：日常轻度使用，月费用大约 $5-$15。建议在 Anthropic Console 设置月度上限，防止意外超支。

1.3 启动 Claude Code

cd 你的项目目录    # 先进入项目文件夹<br>claude             # 启动<br>

看到 > 提示符后就可以对话了。试试第一句话：

> 你好，请用中文介绍一下你自己，以及你能帮我做什么<br>

第一个作品：创建 hello.html

试试让 Claude 做点实际的事情：

> 请在当前目录创建一个叫 hello.html 的文件，内容是一个简单的网页，<br>> 标题写"我的第一个AI作品"，页面中间用大号字显示"Hello World! 这是 Claude Code 帮我做的 🎉"<br>

Claude 会在你面前实时编写代码并创建文件。完成后：

- Mac 用户：open hello.html

- Windows 用户：explorer.exe hello.html

你的浏览器会打开这个网页——这就是 Claude Code 帮你创建的第一个作品。

退出方式：输入 /exit 或按 Ctrl + C 两次。

1.4 常见安装问题排查

❓ 输入 claude 后提示 "command not found"

说明安装没有成功，或者 PATH 没有设置好。尝试：

1. 重新运行安装命令

1. 关闭终端，重新打开一个新的终端窗口

1. 再次输入 claude --version 检查

❓ 提示认证失败 / API Key 无效

1. 确认你的 API Key 以 sk-ant- 开头

1. 确认你在 Anthropic Console 中已添加付款方式

1. 重新设置环境变量（检查有没有多余的空格或引号）

❓ Claude 回复很慢

1. 检查网络连接是否正常（可能需要代理/VPN）

1. 用 /model sonnet 切换到更快的模型

1. 用 /compact 压缩对话历史，释放上下文空间

❓ 对话越来越不准确

这是对话太长导致的「上下文疲劳」。解决方法：

1. 输入 /compact 压缩历史

1. 或者输入 /clear 清空，重新开始

1. 复杂任务建议拆成多次短对话

❓ Claude 执行了我不想要的操作

不要慌。Claude Code 在执行操作前通常会请求确认。如果发现操作有误：

1. 按 Esc 键立即停止当前生成

1. 在确认提示 [Y/n] 时输入 n 拒绝执行

1. 如果已经执行了，可以说「撤销刚才的修改」

4实用技巧

4.1 用 ! 直接执行命令

加 ! 前缀可以直接运行命令，省去 Claude 思考的时间和费用：

> ! git status<br>> ! dir<br>> ! npm test -- --filter=auth<br>

这样可以省去 Claude 思考的时间和 Token 消耗。

4.2 用 @ 引用文件

用 @ 可以直接让 Claude 读取指定文件：

> 请阅读 @README.md 并告诉我这个项目是做什么的<br>> 看看 @src/components/Header.tsx 有什么问题<br>

4.3 用 think 触发深度思考

复杂问题前加 think 或 think hard，让 Claude 先深入思考再回答：

> think: 我们的产品日活从 5000 涨到了 50000，但付费转化率从 5% 降到了 2%，可能的原因有哪些？<br><br>> think hard: 请帮我设计一个完整的用户增长漏斗分析框架，包含关键指标、数据采集点和分析方法<br>

4.4 拖拽文件到终端

图片、PDF、CSV 等文件可以直接拖拽到终端窗口，自动填入路径：

> 请分析 /Users/yourname/Desktop/report.pdf 的主要结论<br>

4.5 粘贴图片

Claude Code 支持直接粘贴图片（Ctrl+V）。可以粘贴 UI 设计稿让它照着实现，或粘贴报错截图让它诊断。

4.6 设置预算上限

担心费用失控？启动时设限：

claude --max-budget-usd 5<br>

这次对话最多花 $5，到了上限自动停止。

4.7 权限模式

按 Shift + Tab 可以在三种模式间切换：

模式 说明
建议模式（默认） Claude 先告诉你计划，你确认后才执行
自动模式 自动批准安全操作
Plan Mode 只读不写，用于探索和规划
⚠️ 注意：即使是自动模式，涉及删除文件等破坏性操作时，Claude Code 仍然会要求你确认。

白名单常用命令

把你信任的命令加入白名单，Claude 执行它们时就不会问你了。输入 /permissions 进入管理。常见的白名单候选：

npm test<br>npm run lint<br>git status<br>git diff<br>git log<br>

检查点机制

每次 Claude 编辑文件前，它会自动对文件做快照。如果改坏了：

- 按两次 Esc → 回退到上一步

- 或者直接说「撤销刚才的修改」

⚠️ 检查点只覆盖文件修改。如果 Claude 执行了影响外部系统的操作（如调用 API、修改数据库），那是无法回退的——这就是为什么 Claude 在执行这类命令前会特别谨慎地征求同意。

4.8 键盘快捷键速查

快捷键 功能

Esc 停止 Claude 当前生成
Ctrl + C 按两次退出 Claude Code
Shift + Enter 多行输入时换行
Ctrl + V 粘贴图片
↑ / ↓ 浏览历史输入

5核心概念详解

5.1 Skill（技能）—— 给 Claude Code 装"技能包"

🎯 一句话理解：Skill 就是你预先写好的"操作手册"，告诉 Claude Code "遇到某类任务时，按这个步骤来做"。

为什么需要 Skill？

每次重复说明流程很麻烦。Skill 把流程打包成一个命令，以后只需要输入 /deploy 就行了。

Skill 的本质

就是一个 .md 文件，用自然语言写清楚执行步骤。就像你写给同事的操作手册，只不过"同事"换成了 Claude Code。

两种 Skill 类型

类型 说明 触发方式
参考型 Claude 需要时自动加载 自动，不用管
工作流型 你主动用 /命令 触发 手动输入命令

参考型示例（API 规范）：

# .claude/skills/api-conventions/SKILL.md<br>---<br>name: api-conventions<br>description: 我们的 REST API 设计规范<br>---<br>- URL 用 kebab-case（如 /user-profiles）<br>- JSON 字段用 camelCase（如 userName）<br>- 列表接口必须支持分页<br>

当 Claude 写 API 代码时，会自动参考这个规范。

工作流型示例（修复 Issue）：

# .claude/skills/fix-issue/SKILL.md<br>---<br>name: fix-issue<br>description: 修复 GitHub Issue 的标准流程<br>---<br>修复 GitHub Issue: $ARGUMENTS<br><br>1. 用 `gh issue view` 查看 Issue 详情<br>2. 理解问题描述<br>3. 搜索相关代码<br>4. 实现修复<br>5. 写测试并运行<br>6. 确保 lint 和类型检查通过<br>7. 写描述性 commit message<br>8. push 并创建 PR<br>

使用时输入 /fix-issue 1234 即可。

CLAUDE.md vs Skill 怎么选？

5.2 MCP（模型上下文协议）—— 让 Claude Code 连接外部世界

💡 一句话理解：MCP 就是一个"插头"，让 Claude Code 能连接飞书、GitHub、数据库等外部服务。

用比喻理解 MCP

想象 Claude Code 是一个很聪明的人，但被关在一间屋子里（你的电脑终端）。

MCP 就是给这个屋子装了很多扇窗户和门：

- 通过"飞书窗户"读写飞书文档

- 通过"GitHub 门"操作代码仓库

- 通过"数据库窗户"查询数据

每扇"窗户"就是一个 MCP 服务器。

怎么配置？

在配置文件中添加 MCP 服务器：

// ~/.claude/settings.json<br>{<br>  "mcpServers": {<br>    "feishu": {<br>      "command": "npx",<br>      "args": ["-y", "@anthropic-ai/feishu-mcp-server"],<br>      "env": {<br>        "FEISHU_APP_ID": "你的应用ID",<br>        "FEISHU_APP_SECRET": "你的应用密钥"<br>      }<br>    }<br>  }<br>}<br>

配置后重启 Claude Code 即可生效。

也可以用命令行添加：

claude mcp add github -- gh-mcp<br>claude mcp add postgres -- pg-mcp --connection-string "postgresql://..."<br>

实际案例

> 帮我读取这个飞书文档的内容：https://mi.feishu.cn/wiki/xxxxx<br>> 查看 GitHub Issue #42 的详情，然后实现它<br>> 查询数据库中上周新增用户数<br>
⚠️ 注意：每个 MCP Server 会占用上下文空间。装太多会吃掉大量空间。用 /mcp 命令查看占用情况，按需启停。
💡 小贴士：MCP 服务器有很多现成的，可以在 MCP 市场（如 mcp.so）搜索你需要的工具。

5.3 CLAUDE.md（项目记忆文件）—— 告诉 Claude "我们项目的规矩"

💡 一句话理解：CLAUDE.md 就是你写给 Claude Code 的"项目说明书"，每次启动时它会自动阅读。

快速创建

在项目文件夹里启动 Claude Code 后，输入：

/init<br>

Claude 会自动扫描项目，帮你生成 CLAUDE.md。

手动创建示例

# 项目说明<br><br>这是一个电商后台管理系统。<br><br>## 技术栈<br>- 前端：React 18 + TypeScript + Ant Design<br>- 后端：Node.js + Express + Prisma<br><br>## 常用命令<br>- 启动：`npm run dev`<br>- 测试：`npm test`<br>- 构建：`npm run build`<br><br>## 代码规范<br>- 使用 TypeScript，不要写 JavaScript<br>- 组件使用函数式组件<br>- 文件命名使用 camelCase<br>- 提交信息使用中文<br><br>## 注意事项<br>- IMPORTANT: 修改数据库迁移文件前必须先问我<br>- src/config/ 包含敏感信息，不要提交到 git<br>

写 CLAUDE.md 的核心原则

只写 Claude 无法自己推断出来的东西。

✅ 应该写的：

- 构建和测试命令

- 代码规范中的特殊约定

- 重要注意事项（用 IMPORTANT: 标记）

❌ 不应该写的：

- Claude 读代码就能知道的（如"这个项目用 React"）

- 标准语言约定（如"Python 用 4 空格缩进"）

- 经常变化的信息

💡 检验标准：对每一行问自己——"删掉这行，Claude 会犯错吗？"如果不会，就删掉。臃肿的 CLAUDE.md 反而会让 Claude 忽略重要指令。

用 @ 导入其他文件

CLAUDE.md 支持 @路径 语法引用其他文件，避免重复维护：

项目概览请看 @README.md<br>可用命令请看 @package.json<br><br># 其他规范<br>- Git 工作流：@docs/git-workflow.md<br>- 个人偏好：@~/.claude/my-preferences.md<br>

模块化规则

规范太多？用 .claude/rules/ 目录拆分：

.claude/<br>├── CLAUDE.md              # 主文件：核心规范<br>└── rules/<br>    ├── code-style.md      # 代码风格<br>    ├── testing.md          # 测试约定<br>    └── api-design.md       # API 设计规范<br>

.claude/rules/ 下的所有 .md 文件会自动加载。还可以用 YAML 前置信息限定规则只在处理特定文件时生效：

---<br>paths: src/api/**/*.ts<br>---<br># API 开发规则<br>- 所有接口必须做输入校验<br>- 使用标准错误响应格式<br>

这样只有当 Claude 处理 src/api/ 下的 TypeScript 文件时，这些规则才会激活。

记忆的层级体系

Claude Code 支持多层记忆，从全局到局部：

层级 文件位置 作用范围
全局 ~/.claude/CLAUDE.md 所有项目通用
项目 项目/CLAUDE.md 当前项目
规则 .claude/rules/*.md 按条件加载
Skill .claude/skills/*/SKILL.md 按需加载

启动 Claude Code 时，这些文件全部自动加载。

Memory vs CLAUDE.md

对比项 CLAUDE.md Memory

5.5 Plan Mode（规划模式）—— 先看计划，再动手

🎯 一句话理解：Plan Mode 让 Claude 先把"施工计划"给你看，你批准后才开始干活。

最佳工作流：探索 → 规划 → 执行

第一步：探索（按 Shift+Tab 进入 Plan Mode）

> 读一下 src/auth/ 目录，帮我理解登录流程是怎么实现的<br>

第二步：规划（还在 Plan Mode）

> 我想加上 Google OAuth 登录。需要改哪些文件？给我一个详细计划<br>

第三步：执行（再按 Shift+Tab 切回 Normal Mode）

> 按照刚才的计划实现 OAuth 流程，写好后跑一下测试<br>

第四步：提交

> 用描述性的 commit message 提交代码，然后开一个 PR<br>
💡 什么时候不需要规划？ 简单任务直接做——改个拼写错误、加一行日志。如果你能一句话描述清楚要改什么，就跳过规划。

5.6 子代理（Sub-agents）—— 给 Claude 配"小弟"

💡 一句话理解：子代理是 Claude 派出的"分身"，在独立的上下文中完成子任务，做完只把结论带回来。

为什么需要子代理？

上下文窗口是有限的。如果一个任务需要读 50 个文件，全塞进主对话空间就满了。

子代理解决这个问题：它在独立的上下文窗口里工作，就像让实习生去做调研，ta 看了 100 页材料，最后给你一页摘要。

使用方式

你不需要手动创建，当任务复杂时 Claude 会自动决定。也可以主动建议：

> 帮我做一个代码库审计。用子代理分别检查：<br>> 1. 安全漏洞<br>> 2. 性能问题<br>> 3. 代码规范违规<br>> 最后汇总给我一份报告<br>

自定义子代理

在 .claude/agents/ 目录下创建：

# .claude/agents/reviewer.md<br>---<br>name: reviewer<br>description: 代码审查代理<br>model: sonnet<br>---<br>你是一个高级代码审查员。审查时关注：<br>1. 代码质量和可读性<br>2. 潜在的 Bug<br>3. 安全隐患<br>4. 性能问题<br>给出具体的改进建议，引用代码行号。<br>
💡 PM 实用场景：你可以创建一个「PRD 审查员」子代理，让它专门检查 PRD 中的逻辑漏洞、缺失的用户故事、不清晰的验收标准。

5.7 Hooks（钩子）—— 自动化的"规则引擎"

🎁 一句话理解：Hook 是在特定节点强制自动执行的脚本。CLAUDE.md 是"建议"，Hook 是"必须执行"。

适用场景

- 每次编辑文件后自动跑 ESLint

- 禁止 Claude 修改某些敏感文件

- 每次提交前自动运行测试

创建方式

最简单的方式——让 Claude 帮你写：

> 帮我写一个 Hook：每次编辑文件后自动运行 eslint<br>> 再写一个 Hook：禁止修改 migrations/ 文件夹里的文件<br>

也可以用 /hooks 命令进入交互式配置界面。

8进阶技巧

8.1 Claude Code 是怎么工作的？—— 代理循环

理解 Claude Code 背后的工作逻辑，会帮你写出更好的指令、更快拿到想要的结果。

代理循环：收集 → 行动 → 验证

每次你给 Claude 一个任务，它都会经历三个阶段：

你的指令<br>  ↓<br>① 收集上下文（读文件、搜索代码、看项目结构）<br>  ↓<br>② 采取行动（编辑文件、运行命令、生成代码）<br>  ↓<br>③ 验证结果（运行测试、检查输出、对比预期）<br>  ↓<br>如果不对 → 回到 ① 继续调整<br>如果通过 → 交付结果<br>

这就是「代理循环」（Agentic Loop）。Claude 不是简单地生成一段文字——它会像一个真正的工程师一样，边做边检查、边改边学。

你是循环的一部分。 你可以随时按 Esc 中断 Claude，给它补充信息或纠正方向。你不需要等它做完才说话。

四类内置工具

Claude Code 之所以能「动手干活」，是因为它有四类工具：

工具类型 作用 示例
文件读写 创建、编辑、删除文件 创建组件、修改配置
终端命令 执行 shell 命令 运行测试、安装依赖
搜索工具 在代码库中搜索 找函数定义、搜索关键词
子代理 派出独立分身 并行检查多个维度

Claude 会根据你的指令自动选择用哪些工具。你说「修复这个测试」，它可能会：先运行测试看哪个失败 → 读错误信息 → 搜索相关代码 → 改代码 → 再跑测试验证。整个过程自动串联。

8.2 上下文窗口管理

上下文窗口（Context Window）是 Claude 的「工作记忆」。你的对话、Claude 读过的文件、运行过的命令输出——全都塞在里面。

关键点：上下文窗口是有限的。 一旦塞满，Claude 的表现会明显下降——它会「忘记」早期的指令，犯更多错误。

命令 作用
/clear 清空上下文，新任务开始前用
/compact 压缩历史，保留关键信息丢弃细节
/context 查看上下文使用情况
💡 核心原则：每个新任务开始前用 /clear，对话变慢时用 /compact，持久化规则写进 CLAUDE.md 而不是靠对话记忆。

8.3 提示词的进阶技巧

委派，不要指令

❌ 不好的方式：

> 打开 src/auth/login.ts，找到第 42 行的 refreshToken 函数，<br>> 把 if 条件改成 token.expiry < Date.now() - 60000<br>

✅ 更好的方式：

> 登录流程中，用户的 token 过期后刷新失败了。<br>> 相关代码在 src/auth/ 目录。帮我查一下问题并修复它。<br>

把 Claude 当成有能力的同事来委派任务，给它方向和上下文，让它自己决定怎么做。

提供验证标准

给 Claude 一种自我检查的方式，有测试用例它就能跑测试，有截图它就能对比。

验证方式 示例
跑测试 "修好后运行 npm test 确认通过"
对比截图 "粘贴设计稿，实现后截图对比"
检查错误 "确保浏览器控制台没有报错"
类型检查 "运行 pnpm typecheck 确保没有类型错误"

8.4 模型选择指南

模型 特点 适用场景 价格
Sonnet 快速、性价比高 日常使用，大多数任务 中等
Opus 更强大、更贵 复杂推理、长文档分析 较贵
Haiku 最快、最便宜 简单问答 最便宜

用 /model 切换。大部分时间用 Sonnet 就够了。

8.5 省钱实战指南

Claude Code 按 Token 计费，Token 就是 AI 处理文本的基本单位。

技巧 说明
选对模型 日常用 Sonnet，复杂任务才用 Opus
管理上下文 用 /clear 和 /compact 减少无效 token
精准提示词 "修复 src/auth/login.ts 的 token 刷新 bug" 比 "修复那个 bug" 省很多
设预算上限 claude --max-budget-usd 5 限制单次会话费用
用 ! 执行命令 省去 Claude 思考的 token
💰 费用参考：使用 Sonnet，平均每位开发者每天约 $6，90% 的用户每天不超过 $12。作为轻度使用预计远低于此。

1. 检查结果 — Claude Code 的输出不一定完美，养成检查的习惯

1. 用 CLAUDE.md 保存项目规范 — 避免每次重复说明

1. 给 Claude 自我检查的方式 — "修好后跑测试确认" 比 "修好就行" 效果好得多

1. 把 Claude 当同事委派 — 给方向和上下文，不要写微操指令

❌ 避免这样做

1. ❌ 不要一句话描述模糊需求（"帮我做个网站"）

1. ❌ 不要让它一次性修改太多不相关的文件

1. ❌ 不要忽略它的确认提示直接说"全部同意"

1. ❌ 不要在不清楚后果的情况下让它执行删除操作

1. ❌ 不要在一个超长对话里塞太多不相关的任务

1. ❌ 不要写过于详细的微操指令（"打开第42行，改成..."）——委派给它

10常见问题

基础问题

Q: 完全不懂编程，能用 Claude Code 吗？A: 能！核心交互方式是自然语言——你用中文告诉它想做什么就行。它会帮你写代码、执行命令、创建文件。你只需要检查结果是否符合预期。

Q: 使用 Claude Code 要花多少钱？A: 用 /cost 查看费用。日常轻度使用月费约 $5-$15，建议在 console.anthropic.com 设置月度上限。

Q: 对话太长、响应变慢怎么办？A: 用 /compact 压缩历史，或 /clear 清除重新开始。复杂任务建议拆成多次短对话。

Q: Claude Code 写的代码有 Bug 怎么办？A: 直接告诉它："运行时报错了，错误是 xxx，帮我修复。"

Q: 怎么让 Claude Code 记住我的偏好？A: 两种方式：写在 CLAUDE.md 里（永久生效），或直接说"记住：xxx"。

Q: Claude Code 会不会把我电脑搞坏？A: 它在执行任何操作前都会先告诉你并等你确认。仔细看操作说明再确认就不会有问题。

Q: Claude Code 和 OpenClaw 必须一起用吗？A: 不需要，完全独立。你可以只用其中一个，装了两个也互不干扰。

Q: 这些工具安全吗？A: Claude Code 是 Anthropic 官方产品，传输加密。但发给 AI 的内容会发送到服务器处理，请避免发送密码、银行卡号等敏感信息。

Claude Code 相关

Q: Claude Code 和 claude.ai 网页版有什么区别？A: claude.ai 网页版是一个聊天界面，你只能在网页上对话。Claude Code 运行在你的电脑终端里，它能直接读写你电脑上的文件、运行命令、理解整个项目。简单说：网页版只能聊天，Claude Code 能动手干活。

Q: 对话太长了，Claude 开始「犯傻」怎么办？A: 这是上下文窗口接近满载的正常现象。输入 /compact 压缩历史，或 /clear 清空重来。建议复杂任务拆成多次短对话。

Q: Claude 执行了我不想要的操作怎么办？A: 1. 按 Esc 立即停止生成；2. 确认提示时输入 n 拒绝；3. 如果已执行，说"撤销刚才的修改"。

OpenClaw 相关

Q: 飞书免费版能用 OpenClaw 吗？A: 能。自建应用和机器人功能对所有飞书版本开放，包括免费版。

Q: 飞书机器人需要服务器吗？A: 不需要。OpenClaw 使用 WebSocket 长连接，你的电脑直接连接飞书云端，不需要公网 IP。

Q: 能同时连飞书和 WhatsApp 吗？A: 能。OpenClaw 原生支持多渠道同时在线，互不影响。
